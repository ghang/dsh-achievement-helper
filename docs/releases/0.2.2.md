# 0.2.2 · npm trusted publishing

Release maintenance now includes a dedicated GitHub Actions workflow for npm
OIDC authentication. Once its trusted-publisher binding has been configured,
publishing a GitHub Release triggers npm publication of the same frozen tarball.
There is no long-lived npm publishing token in the workflow.

Before uploading, the job checks the annotated tag, package identity, exact
source commit's successful Node 22/24 CI, and the GitHub assets' server SHA-256
digests. Only the versioned tarball is read for npm upload; its fixed-name alias
is checked through the server digest. A matching existing npm version is verified
without being republished. Uncertain writes require a state check before retry.

This release changes publishing infrastructure and documentation. Runtime code,
Windows compatibility fixes, stored data and four model-tool schemas remain as
in 0.2.1. Upgrade and rollback use the existing complete-storage backup procedure.
Workflow configuration alone does not prove publication: the Actions receipt and
exact public npm version must both be checked.
