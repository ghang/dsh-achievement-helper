# 0.2.1 · Windows compatibility fixes

On Windows, saving an archive could complete the file write and replacement but
still report a storage error when the subsequent parent-directory operation
returned `EPERM`. The journal, generation receipts and debug copies now share
one compatibility rule for that Windows directory operation. Actual file-write,
file-sync and rename errors still fail; other directory errors retain the
committed-state warning and original cause.

The achievement center and debug banner now clear the Windows desktop caption
row using the host's published height, with a 40px fallback. Fullscreen removes
that reservation. Narrow and short windows fit the remaining space; Web and
macOS retain their placement and background blur.

Existing journal data, identities, points, draws, equipment and four model-tool
schemas are unchanged. Back up the plugin storage before upgrading as described
in the README. This patch does not perform a data migration or import history.

Verification covers synthetic Windows error injection against all three writers,
retained failures and error causes, Windows drive/UNC collector paths, source
and unpacked-package integration, and browser geometry with Windows host markers.
These checks do not constitute a native Windows Electron host test.

The package version and local candidate do not by themselves confirm public
publication; use the exact GitHub Release and npm version metadata to check
availability.
